# kagami_contrib — тесты к файлам Владимира Заводюка

Папка добавлена с согласия автора. **Ни один файл автора не изменён:** тесты загружают их как есть, по имени.
Автор кода W4, W5.5+Game, ZVD-TETRA и ZVD-60D — Владимир Заводюк, All rights reserved.
Тесты и инструменты в этой папке — вклад Галина Димитрова (КАГАМИ ЕООД).

## Запуск

```bash
cd kagami_contrib
pip install -r requirements.txt        # numpy, pytest; для ZVD ещё numba, для 60D v3 — zstd и opencv-python
python -m pytest
```

### Как читать результат

- **passed** — работает как ожидается.
- **xfail** — известная особенность: тест описывает поведение, которого ждут от контура, но сейчас его нет. Причина записана в самом тесте.
- **XPASS** — особенность исправлена, тест можно делать обычным.
- **skipped** — тест не мог запуститься, причина напечатана.

### ZVD-60D v3: что найдено (xfail)

1. **Текст не восстанавливается.** Строки 561–562 (`reconstructed_bytes[:] = source_bytes[:]`) делают остаток всегда нулевым — в куб попадают нули. **Проверено: если удалить эти две строки, все 4 текстовых теста проходят** (XPASS).
2. **Видео:** `pop_frames` возвращает разности между кадрами (5 уровней, −1…+1) и только в выбранных точках, а не сами кадры.
3. Измерение: 5 кадров 40×40 (8000 точек) → 64 000 байт в кубах до zstd.

Свойство логики (тест проходит, это не ошибка кода): Лукасевич по 60 значениям = Σx − 118, поэтому уже четыре значения +1 вместо +2 дают −2. Под нагрузкой (stress ≥ 0,70) конвейер переходит на Лукасевича — и почти всё сворачивается в −2. Стоит подумать о свёртке по группам (12 × 5).

### Известные особенности (xfail), W5.5+Game

1. PASS — только при очень уверенном ответе (~0,97); при 0,85 решение CLARIFY.
2. REJECT не достигается даже при полной неуверенности (0,26 / 0,25 / 0,25 / 0,24).
3. Примерно в 20% случаев лучший кандидат — не самый вероятный вариант.
4. Накопленная память меняет результат: тот же вход даёт другой composite после 300 вызовов.
5. Время вызова растёт с длиной истории.

### ZVD-TETRA: что проверят тесты, когда файл загрузится

- `test_bitstream_roundtrip` — кубы, записанные в `.zvd5t` и прочитанные обратно, совпадают байт в байт.
- `test_text_distinct_inputs_give_distinct_cubes` — разные тексты дают разные кубы (необходимое условие «без потерь»).
- `test_text_roundtrip`, `test_video_roundtrip` — есть декодер, и после раскодирования данные совпадают с исходными.

Пока проверен только путь «пропуска»: тесты ZVD ещё не запускались на рабочей версии файла.

## Инструмент: `tools/roundtrip.py`

Универсальная проверка любого кодека «без потерь»:

```python
from tools.roundtrip import check
report = check(encode, decode, [b"sample 1", b"sample 2"])
print(report)          # сколько совпало байт в байт, где первое расхождение, размер до/после
```
